# 게임 설계 핵심

## 게임 장르 및 핵심 메커니즘

**장르**: 방치형 MMORPG (Idle MMORPG)

**핵심 게임플레이 루프**:
```
던전 입장 → 자동 전투 → 보상 획득 → 캐릭터/장비/스킬 강화
→ PVP 도전 → 길드 활동 → 보스 레이드 → 다음 던전
```

**주요 특징**:
1. **방치형**: 오프라인 자동 사냥, 로그인 시 보상 수령
2. **자동 전투**: 서버 기반 턴제 전투 시뮬레이션
3. **소셜**: 친구, 길드, 실시간 채팅 (SignalR)
4. **협동**: 길드 레이드 (멤버 협력)
5. **경쟁**: PVP 아레나 (ELO 매칭), 랭킹
6. **수익화**: 가챠, VIP, 상점
7. **라이브 운영**: 일일 미션, 출석, 이벤트, 우편함

## 서버 권위 설계 철학

### 핵심 원칙

**1. 모든 중요 로직은 서버에서 계산**
- 전투 결과 (승패, 데미지)
- 보상 계산 (경험치, 골드, 드랍)
- 가챠 확률 (Legendary 1%, Epic 9%, Rare 30%, Common 60%)
- 장비 강화 성공/실패

**2. 클라이언트는 표현만**
- UI 표시, 애니메이션, 입력 전달
- **클라이언트 데이터는 절대 신뢰하지 않음**

**3. 검증 계층**
```
클라이언트 요청 → API Controller → Service (비즈니스 검증)
→ Repository (DB 저장) → 응답
```

### 치팅 방지 사례

**✅ 올바른 설계** (서버 계산)
```csharp
// 서버가 전투를 시뮬레이션
[HttpPost]
public IActionResult BattleStart([FromBody] BattleStartRequest request)
{
    var result = _battleService.Simulate(characterId, monsterId);
    character.Gold += result.CalculatedGold;  // ✅ 서버가 계산한 Gold
    _repository.Update(character);
    return Ok(result);
}
```

## 핵심 엔티티 관계

### Player-Character 관계 (1:N)
```
Player (1) → Characters (N)
- 한 플레이어가 여러 캐릭터 보유
- 각 캐릭터는 독립적 진행도
```

### Character-Equipment 관계 (1:N)
```
Character (1) → Equipments (N)
- OwnerId: 소유자 (인벤토리)
- CharacterId (nullable): 장착 중인 캐릭터
```

### Character-Skill 관계 (M:N)
```
Character (M) ↔ Skills (N) via PlayerSkill
- PlayerSkill: 중간 테이블
- SkillLevel: 스킬별 레벨
- SlotIndex: 장착 슬롯 (1-6)
```

### DungeonStage-Monster 관계 (N:1)
```
DungeonStages (N) → Monster (1)
- 여러 스테이지가 같은 몬스터 사용 가능
- MonsterId: FK (RESTRICT)
```

## 게임 경제 설계

### 재화 종류

**1. Gold (기본 재화)**
- 획득: 던전 클리어, 오프라인 보상
- 사용: 장비 강화, 상점 구매

**2. Crystal (프리미엄 재화)**
- 획득: 던전 첫 클리어, 일일 미션, 유료 구매
- 사용: 스킬 가챠, VIP 구매

**3. 기타 재화**
- 강화석, 스킬 포인트, VIP 포인트

### 경제 밸런스 원칙

**1. Sink vs Faucet**
```
Faucet (재화 획득): 던전, 오프라인, 미션
Sink (재화 소모): 강화, 가챠, 상점
→ Sink > Faucet (적당한 부족 유지)
```

**2. 병목 구간**
```
Level 10, 20, 30: 던전 난이도 급증
→ 장비 강화 필요
→ Gold Sink 발생
```

**3. 수익화 포인트**
```
- 오프라인 시간 연장 (VIP)
- 스킬 가챠 크리스탈 구매
- 강화 성공률 증가 아이템
```

## 개발 우선순위 원칙

1. **서버 로직 먼저**: 비즈니스 규칙 확정 후 Unity 연동
2. **단위 테스트**: 확률, 계산 로직은 반드시 테스트
3. **밸런스 조정 용이**: 상수를 Configuration 테이블로 관리
4. **로그 기록**: 모든 재화 변동, 가챠 결과 로그

### 점진적 복잡도
1. **MVP**: 단순한 턴제 전투, 고정 확률
2. **확장**: 스킬 추가, 턴 순서 계산
3. **고급**: 버프/디버프, 크리티컬, 회피
