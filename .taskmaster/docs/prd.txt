# IdleRPG Game Design Document (GDD)
**Version:** 1.0
**Last Updated:** 2025-10-01
**Project Type:** 서버 기술 학습용 방치형 RPG (Clean Architecture)

---

## 📋 프로젝트 개요

### 목적
- **주 목표:** ASP.NET Core 서버 기술 스택 습득 (포트폴리오)
- **부 목표:** Unity 클라이언트 개발 경험 확장
- **게임 장르:** 버섯커 키우기 스타일 성장 중심 방치형 RPG

### 핵심 가치
- ✅ 서버 기술 학습에 최적화된 기능 선정
- ✅ 점진적 개발 (주차별 1개 컨텐츠)
- ✅ 깔끔한 API 설계 (RESTful + 문서화)
- ✅ Clean Architecture 실전 적용

### 기술 스택

**서버 (ASP.NET Core 8.0)**
- Framework: .NET 8.0, ASP.NET Core Web API
- Database: PostgreSQL + Entity Framework Core 9.0
- Caching: Redis (Ranking, Session)
- Real-time: SignalR (Chat)
- Patterns: Clean Architecture, CQRS (MediatR), Repository
- Validation: FluentValidation
- Logging: Serilog (Structured Logging)
- Background Jobs: Hangfire (Scheduled Tasks)
- Mapping: AutoMapper

**클라이언트 (Unity 2022 LTS)**
- Network: UnityWebRequest, WebSocket (SignalR Client)
- UI: TextMeshPro, DOTween
- Architecture: MVC or MVP Pattern
- State Management: FSM (Finite State Machine)

## 🎮 게임 컨셉

### 핵심 게임 루프
```
1. 플레이어 가입/로그인 (JWT 인증)
2. 캐릭터 생성
3. 장비 착용
4. 자동 사냥 시작 (방치)
5. 경험치/골드/아이템 획득 (오프라인 보상)
6. 레벨업 & 스탯 강화
7. 상점에서 장비 구매
8. 더 높은 스테이지 도전
9. 퀘스트 완료 & 랭킹 경쟁
```

### 게임 특징
- **방치형:** 게임 종료 중에도 캐릭터 자동 성장
- **서버 검증:** 전투 결과는 서버에서 시뮬레이션 (치팅 방지)
- **실시간 요소:** 채팅, 랭킹 업데이트
- **주기적 컨텐츠:** 일일 퀘스트, 출석 보상

### Week 1: 캐릭터 시스템
**목표:** 플레이어가 캐릭터를 만들고 레벨업한다

#### 서버 작업
1. Character Entity 생성
   - Id, PlayerId, Name, Level, Experience
   - Strength, Dexterity, Intelligence, Vitality
   - StatPoints, Gold, CreatedAt

2. Character Repository & Service
   - CreateCharacterAsync
   - GetCharactersByPlayerIdAsync
   - GetCharacterByIdAsync
   - AddExperienceAsync (레벨업 로직 포함)
   - AllocateStatPointAsync

3. API Endpoints
   - POST /api/characters (캐릭터 생성)
   - GET /api/characters (내 캐릭터 목록)
   - GET /api/characters/{id} (캐릭터 상세)
   - POST /api/characters/{id}/experience (경험치 획득)
   - PUT /api/characters/{id}/stats (스탯 분배)

4. 비즈니스 규칙
   - 플레이어당 최대 3개 캐릭터
   - 이름 2-20자, 중복 불가
   - 레벨업 시 스탯 포인트 5개 지급
   - 레벨별 필요 경험치: Level * 100

#### 클라이언트 작업
1. CharacterData 모델 클래스
2. CharacterAPI 네트워크 클래스
3. CharacterCreateScene UI
   - 이름 입력 TextField
   - 생성 버튼
   - 에러 메시지 표시
4. CharacterListScene UI
   - 캐릭터 슬롯 (최대 3개)
   - 선택 버튼
5. CharacterInfoPanel UI
   - 이름, 레벨, 경험치 바
   - 스탯 표시 (STR, DEX, INT, VIT)
   - 스탯 포인트 분배 버튼

### Week 3: 전투 시뮬레이션 (서버)
**목표:** 서버에서 전투를 계산하고 검증한다

#### 서버 작업
1. Entities
   - MonsterTemplate
   - CombatLog

2. Seed Data
   - 몬스터 20종 (슬라임, 고블린, 오크, 드래곤 등)

3. CombatSimulator
   - CalculateDamage (공격력, 방어력 기반)
   - SimulateCombat (턴제 시뮬레이션)
   - CalculateRewards (경험치, 골드, 드롭)

4. API Endpoints
   - GET /api/monsters (몬스터 목록)
   - POST /api/combat/start (전투 시작)
   - GET /api/combat/{id}/result (전투 결과)

5. 비즈니스 규칙
   - 데미지 = (공격력 - 방어력/2) * (0.9~1.1 랜덤)
   - 크리티컬 10% 확률 (데미지 1.5배)
   - 승리 시: 경험치, 골드 획득
   - 패배 시: 경험치 10%, 골드 손실 없음

#### 클라이언트 작업
1. MonsterData 모델
2. CombatScene UI
   - 캐릭터 스프라이트 (좌측)
   - 몬스터 스프라이트 (우측)
   - HP 바 (양쪽)
   - 데미지 텍스트 애니메이션
3. CombatResultPopup
   - 승리/패배 표시
   - 획득 보상 표시
4. 전투 애니메이션 (간단한 공격 모션)

### Week 4: 자동 사냥 & 오프라인 보상
**목표:** 게임을 켜지 않아도 캐릭터가 성장한다

#### 서버 작업
1. Background Service
   - AutoHuntingService (시간당 진행 계산)
   - 1분마다 활성 사냥 캐릭터 확인
   - 경과 시간 * 시간당 획득량 계산

2. OfflineRewardCalculator
   - 로그아웃~로그인 시간 차이 계산
   - 최대 24시간 보상 (그 이상은 24시간으로 제한)

3. API Endpoints
   - POST /api/characters/{id}/hunting/start (사냥 시작)
   - POST /api/characters/{id}/hunting/stop (사냥 중지)
   - GET /api/characters/{id}/hunting/status (현재 상태)
   - POST /api/characters/{id}/rewards/claim (오프라인 보상 수령)

4. 비즈니스 규칙
   - 시간당 전투 10회
   - 전투당 보상 = 몬스터 기본 보상
   - 오프라인 최대 24시간
   - 사냥 중 스테이지 변경 불가

#### 클라이언트 작업
1. AutoHuntingPanel UI
   - "사냥 시작" 버튼
   - 경과 시간 표시
   - 실시간 획득량 표시
2. OfflineRewardPopup
   - 오프라인 시간 표시
   - 획득한 경험치/골드 표시
   - "확인" 버튼
3. 자동 갱신 (10초마다 현재 상태 조회)

## 🔗 클라이언트-서버 연동 가이드

### Unity에서 API 호출 예시

```csharp
// NetworkManager.cs (싱글톤)
public class NetworkManager : MonoBehaviour
{
    private const string BASE_URL = "https://localhost:7122/api";
    private string jwtToken;

    // 로그인
    public async Task<LoginResponse> LoginAsync(string username, string password)
    {
        var request = new LoginRequest { Username = username, Password = password };
        var json = JsonUtility.ToJson(request);

        using var www = UnityWebRequest.Post($"{BASE_URL}/auth/login", json, "application/json");
        await www.SendWebRequest();

        if (www.result == UnityWebRequest.Result.Success)
        {
            var response = JsonUtility.FromJson<LoginResponse>(www.downloadHandler.text);
            jwtToken = response.token;
            return response;
        }
        throw new Exception(www.error);
    }

    // 캐릭터 생성
    public async Task<CharacterDto> CreateCharacterAsync(string name)
    {
        var request = new { name };
        var json = JsonUtility.ToJson(request);

        using var www = UnityWebRequest.Post($"{BASE_URL}/characters", json, "application/json");
        www.SetRequestHeader("Authorization", $"Bearer {jwtToken}");
        await www.SendWebRequest();

        return JsonUtility.FromJson<CharacterDto>(www.downloadHandler.text);
    }
}
```

### SignalR 연동 예시

```csharp
// ChatManager.cs
using Microsoft.AspNetCore.SignalR.Client;

public class ChatManager : MonoBehaviour
{
    private HubConnection hubConnection;

    private async void Start()
    {
        hubConnection = new HubConnectionBuilder()
            .WithUrl("https://localhost:7122/hubs/game")
            .Build();

        hubConnection.On<ChatMessageDto>("ReceiveMessage", (message) =>
        {
            // 메인 쓰레드에서 UI 업데이트
            UnityMainThreadDispatcher.Enqueue(() =>
            {
                chatPanel.AddMessage(message);
            });
        });

        await hubConnection.StartAsync();
    }

    public async void SendMessage(string message)
    {
        await hubConnection.InvokeAsync("SendMessage", new { message });
    }
}
```
